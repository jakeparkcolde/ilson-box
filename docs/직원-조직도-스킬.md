# 직원 · 조직도 · 업무 스킬

기존 `/current/` 관리자의 **우리 회사 → 직원 / 조직도 / 업무 스킬**에서 엽니다. `/people`은 같은 직원 화면으로 이동하며 기존 Box 인증 세션을 사용합니다.

## 직원과 조직도

1. 조직도에서 **조직 바꾸기**를 누르고 팀을 추가합니다. 이름·상위 팀·순서를 편집할 수 있습니다.
2. 직원에서 이름·역할·소개·부서를 입력합니다. 사진이 없으면 범용 얼굴 아바타를 표시하며 실제 활성 상태와 완료 업무 수를 함께 보여줍니다. 직원 상세의 **사진 / 얼굴 변경**에서 사진을 등록하거나 6종 기본 얼굴을 선택합니다.
3. 조직 편집에서 직원을 끌어 이동하거나 **이동할 부서** 선택기를 사용합니다. **저장**하면 조직 전체가 반영되며 **취소**하면 편집을 버립니다. 다른 세션에서 조직이 바뀌면 저장을 거부하고 초안을 유지합니다.
4. 직원 상세의 **업무와 능력**에서 텍스트 지침을 최대 10개 할당하고 맡길 업무를 추가합니다. **지금 실행** 후 **관련 서류·실행 기록**에서 실제 결과를 엽니다.

직원은 이 기기의 AI 업무 역할이며 별도 로그인 계정이 아닙니다. 직원 이름은 중복을 허용하지만 부서·지침 이름은 중복을 허용하지 않습니다. 각 종류는 최대 200개, 맡긴 업무는 전체 1,000개입니다. 범용 조직 템플릿은 확인 후 팀만 추가하며 기존 직원·지침·업무·부서를 삭제하지 않습니다.

순환 관계·없는 부서 참조는 거부합니다. 직원이나 하위 부서가 남은 팀은 삭제할 수 없습니다. 대기·진행 업무가 있는 직원은 삭제할 수 없습니다. 완료·실패 기록과 문서는 직원 삭제 후에도 남습니다. 세션의 공식 `ilson people add` 등록도 같은 장부를 사용하며 목록은 보이는 동안 약 3초 간격으로 갱신합니다. 편집 입력·선택한 상세 탭·조직 초안은 갱신으로 지우지 않습니다.

## 얼굴과 조직도 보기

사진은 JPEG·PNG 2MB 이하, 400만 화소 이하(한 변 최대 4096px)를 지원합니다. 기존 Pillow로 실제 디코딩하고 방향을 보정한 뒤 최대 512px JPEG로 저장하며 EXIF·GPS 등 메타데이터를 제거합니다. 기본 얼굴을 명시적으로 선택해 저장하면 기존 사진은 제거됩니다. 변경 없이 저장하거나 업로드에 실패하면 기존 사진을 유지하며, 실패 후에는 올바른 사진이나 기본 얼굴을 다시 선택해야 저장할 수 있습니다. 직원 삭제 시 사진도 삭제합니다. 사진 파일명·원격 URL·SVG는 서버 파일 경로 또는 실행 코드로 받지 않습니다. 사진 API는 같은 Box 인증과 출처 검증을 사용하고 캐시하지 않습니다. 사진 처리 라이브러리가 없는 설치는 준비 필요 오류를 표시하며 기본 얼굴 선택은 사용할 수 있습니다.

조직도 첫 화면에서 **계층형 / 가로형 / 목록형**을 선택합니다. 계층형은 팀 아래에 하위 팀을, 가로형은 오른쪽에 하위 팀을, 목록형은 팀과 직원을 세로 목록으로 보여줍니다. 가로형의 넓은 트리는 화면 안에서 스크롤할 수 있습니다. 보기 선택은 해당 브라우저에 기억되며 다른 기기와 동기화하지 않습니다.

**공식 / 기능별 / 서비스별 / 플랫** 템플릿은 범용 팀 구성을 미리보기로 추가합니다. 공식은 경영 지원과 사업 운영 아래 기획, 기능별은 기획·운영·지원, 서비스별은 서비스 A·B 및 공통 지원, 플랫은 공통 팀을 제안합니다. 이름이 같은 기존 팀은 그대로 유지합니다. 기존 팀을 없애거나 직원을 자동 재배치하지 않으므로 플랫 선택이 기존 계층을 강제로 평탄화하지 않습니다. 초안에서 직접 직원 배치를 편집한 뒤 저장하거나 취소하세요.

## 맡긴 업무와 정기 업무

**맡긴 업무**는 저장한 요청을 직접 실행하는 장부입니다. 추가·편집·비활성화·삭제할 수 있으며 반복 예약을 생성하지 않습니다.

| 실행 능력 | 실제 경로 | 역할·지침 적용 | 결과 |
|---|---|---|---|
| 문서·답변 작성 | 기존 제한된 Claude CLI 문서 실행기 | 문서 작성 입력 | 회사 서류와 실행 기록 |
| 리서치 | 설정된 기존 native 검색 실행기, 기존 출처 검증 | 조사 요청과 답변 작성·출처 보정 요청 | 리서치 서류와 출처·실행 기록 |
| 지식 수집 | 기존 공개 영상 URL 검증·Aside 수집·Claude 학습 | 수집 자료를 학습하는 모델 입력 | 능력 초안 서류와 실행 기록 |

로그인·지원 도구가 필요한 기능은 기존 설치 상태에 따라 실패할 수 있습니다. 연습용 설치는 외부 모델 실행을 거부합니다. 임의 셸, 도구 전체 권한, 미승인 외부 발송을 추가하지 않습니다. 스킬 설치는 실행 권한을 늘리지 않습니다. 모션·SNS 발행·관리용 예약 스크립트에는 직원 지침을 자동 적용하지 않습니다.

실행 직전에 최신 역할과 **현재 할당된 활성 지침**을 읽습니다. 대기 중 직원·업무가 비활성화되거나 업무가 삭제되면 실행을 실패로 마감합니다. 이미 시작한 실행은 시작 시 지침을 유지하므로 비활성화가 실행 취소를 뜻하지는 않습니다. 결과에 직원·업무·문서 식별자, 적용한 지침과 적용 단계를 남깁니다. 스킬의 마지막 실행은 현재 할당이 아니라 실제 적용 기록에서 조회합니다.

**정기 업무**는 이 Box의 기존 예약 레지스트리입니다. 등록·미등록·멈춤·조회 불가와 실제 plist 일정/마지막 성공 도장을 표시합니다. 직원에게 연결하는 것은 담당 표시이며 스케줄이나 실행 권한을 변경하지 않습니다. 마지막 성공 도장만으로 현재 실행·최근 실패를 단정하지 않습니다. `run-job.sh`의 고정 출력 계약이 있는 아침 브리핑·주간 보고는 실제 저장 보고서를 연결하고, 다른 업무는 연결 가능한 결과가 없음을 표시합니다. 예약 변경은 기존 자동화 현황·`ilson chat` 경로를 사용하세요.

## 스킬 설치와 관리

데스크톱은 유형별 왼쪽 목록과 오른쪽 상세를 함께 보여주며 모바일은 목록과 상세를 전환합니다. **박스 실행 능력**, **설치한 텍스트 지침**, **제공 지침**을 구분합니다. 실행 능력 상세에서 직원을 선택해 맡길 업무를 만들 수 있습니다. 설치 지침 상세는 담당 직원·부서, 본문과 실제 적용 결과를 보여줍니다.

- 제공 지침: 회의 정리·보고서 점검을 미리 보고 설치합니다.
- 직접 추가·파일 설치: 이름·설명·순수 Markdown을 입력하거나 단일 `SKILL.md`를 읽어 검토 후 저장합니다. 파일명을 서버 경로로 쓰지 않습니다.
- 편집·활성화·비활성화·제거를 지원합니다. 제거하면 모든 직원의 해당 할당도 해제하지만 과거 실행 기록은 남습니다.

본문은 24,000자, 파일은 96KB 이하입니다. 선택적 머리말은 한 줄 `name:`·`description:`만 허용하고 제거합니다. hooks·도구 설정·지원 파일·아카이브·원격 URL 설치·쉘 동적 치환은 지원하지 않습니다. 사용자 전역 스킬을 스캔하거나 수정하지 않으며 개인 스킬을 통째로 복사하지 않습니다. 문서·학습 실행기의 무도구·빈 MCP 계약과 리서치 실행기의 기존 웹 전용 허용목록·출처 검증을 유지합니다.

## 저장·업데이트·복구

기존 `.workspace/work.sqlite3` 장부를 사용합니다. 사진·기본 얼굴 선택·소개·맡긴 업무·조직 순서·정기업무 담당은 별도 `people_*` 테이블에 가산하므로 기존 직원 5열 계약을 바꾸지 않습니다. 재설치·업데이트에서 장부를 초기화하지 않고 배포 파일에도 포함하지 않습니다.

조직 저장은 버전 스냅샷을 비교하고 전체 그래프를 검증한 뒤 한 트랜잭션에서 반영합니다. 직원·부서·스킬 참조와 경로·소유권·심볼릭 링크 경계를 유지합니다. 프로필·업무 편집은 오래된 값의 덮어쓰기를 거부합니다. 장부를 직접 편집하는 것은 지원하지 않습니다.

코드 rollback도 런타임 잠금과 대기·실행 업무 검사를 거칩니다. 이전 실행기가 새 직원 연결을 무시하지 않도록 업무가 끝난 뒤에만 복구합니다. 코드 원복은 사용자 장부를 지우지 않으며 이전 버전에서는 신규 메타데이터가 표시되지 않을 수 있습니다. 관리자 종료 후 `.workspace`와 `vault`를 함께 백업하세요.

## 원본 관리자와의 기능 대응

| 원본 관리자 | 설치형 대응 | 제외·차이의 이유 |
|---|---|---|
| 부서별 직원 카드 → 프로필 | 같은 셸 내 카드, 소개·역할·실제 상태 | 실제 직원 이름·사진·조직을 배포하지 않음 |
| 프로필 소개 / 업무·능력 / 서류 | 소개·맡긴 업무 CRUD·실제 실행 / 지침 / 문서·기록 | 계정·성장·신뢰온도는 연결된 측정 자료가 없어 만들지 않음 |
| 대표→팀 드래그 조직도 | 드래그와 선택기, 팀 상위관계·순서, 원자 저장·취소 | 템플릿은 범용 팀 추가만 수행 |
| 정기업무 레지스트리 + 자유 텍스트 duties | 실제 설치 예약 조회와 별도 직접 실행 업무 장부 | 신규 반복 스케줄러를 가장하지 않음 |
| 유형별 스킬 목록·상세 | 실행 능력·설치 지침·제공 지침, 담당·결과 연결 | 개인 도구·외부 실행 훅을 이식하지 않음 |

원본 확인 위치는 `screenStaff`, `screenOrgChart`, `screenProfile`, `screenSkills`와 서버 `build_state`, `_skills`, `_procedure_skills`, `_load_org_layout`, `_save_org_layout`입니다. 운영 데이터는 복사하지 않았습니다.

자동 시험은 조직 원자성·충돌·순환·참조 실패, 이전 버전 직원 CRUD, 실제 provider 프롬프트의 역할/지침과 출처 검증, 비활성/삭제, 인증·입력·기존 CLI 등록을 확인합니다. 브라우저 시험은 격리 HOME와 fake provider를 사용합니다. 실제 모델 품질·과금·실기 배포는 별도 검증 대상입니다.
