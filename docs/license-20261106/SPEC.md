## 1. 목표와 결정

- 공개 저장소의 **소프트 잠금**. Jake가 서명한 시리얼과 서버 상태로 Box 명령·새 기능·팩·업데이트를 제어한다. 코드 수정, 오래된 버전, 수동 복사, 로컬 상태 변경을 막는 보안 경계나 콘텐츠 암호화가 아니다.
- 라이선스 유무와 서버 장애로 설치가 멈추지 않는다. 기존 6.2처럼 설치 때 강의 키트 파일을 만든다. 설치 마지막에 활성화를 제안하되 건너뛸 수 있고, 무인 설치는 기다리지 않는다. OS·의존 도구 등의 실제 실패는 감추지 않는다.
- 최초 오프라인 14일 유예를 허용한다. 서버에 닿으면 등록·취소·기기 수를 재판정한다. 온라인에서 취소 확인 시 즉시 잠근다. 오프라인 기기는 마지막 정상 확인부터 최대 14일 사용할 수 있다. 오프라인에서는 취소와 기기 초과를 바로 알 수 없다.
- 서명 시리얼에는 일련번호·기수·플랜·발급일·서명 만료일·키 ID만 넣고 표시 이름은 서버 DB에만 둔다. 월 납부는 서버 `paid_until`로 연장하며 매월 새 시리얼을 만들지 않는다.
- 개인 서명 키는 Studio의 `~/.config/ilson-license/`에만 둔다. Jake만 발급한다. 키·관리자 비밀·실제 시리얼을 저장소·로그·대화에 남기지 않는다. macmini와 macmini-1에는 접근하지 않는다.
- 일시불 서명 만료는 무기한 또는 충분히 긴 날짜, 월 납부 서명 만료는 발급일로부터 12개월이다. 구체 발급값과 2대 제한·24시간 확인은 아래 제안대로 적용하기 전 확인한다. 14일 유예는 총괄이 승인했다.

## 2. 짧은 시리얼과 서명

시리얼은 평문 인코딩된 bearer credential로, 표시 이름을 담지 않는다. 한글 기수명은 서버에서 표시하고 시리얼에는 **기수 번호**만 넣는다. 실제 형식은 다음 고정 길이 프레임을 제안한다.

| 필드 | 크기 | 인코딩 |
|---|---:|---|
| 버전 | 1 byte | `1` |
| 키 ID | 1 byte | 공개키 선택용 정수 |
| 일련번호 `license_id` | 16 bytes | 암호학적으로 안전한 난수 |
| 기수 | 2 bytes | 1~65535, big-endian |
| 플랜 | 1 byte | 1=일시불, 2=월 납부 |
| 발급일 | 4 bytes | UTC Unix 초, big-endian |
| 서명 만료 | 4 bytes | UTC Unix 초, big-endian; 일시불만 `0xffffffff`를 무기한으로 해석 |
| Ed25519 서명 | 64 bytes | 아래 도메인 분리된 29 bytes에 대한 서명 |

- 서명 입력은 ASCII `ILSON-LICENSE-V1\0` 뒤에 위 29바이트를 그대로 붙인다. 순서·길이·정수 표현을 고정하여 JSON/문자 정규화 문제가 없다. 이름, 연락처, 기기 ID, 매월 납부 상태는 서명에 넣지 않는다. 정확한 바이트와 키 ID를 양쪽에서 동일하게 검증한다.
- 93바이트 전체를 RFC 4648 Base32 대문자 무패딩으로 인코딩하고 `ILSON-` 접두어 뒤 5자 단위로 하이픈을 넣는다. 본문 149자, 구분자를 포함해 약 **184자**다. Ed25519 서명만으로도 Base32 약 103자가 필요하므로 안전한 붙여넣기를 기본으로 한다. 별도 체크섬 없이 길이·인코딩·서명 검증으로 오타를 발견한다. 이 길이는 설계상 계산이며 실제 발급·사용성 시험 전이다.
- 입력은 `ILSON-` 접두어를 요구한다. 접두어 주위와 본문의 ASCII 공백·탭·줄바꿈 및 그룹 하이픈을 허용하고, 영문 소문자는 대문자로 바꾼다. 모호 문자의 자동 치환은 하지 않는다. 과도한 입력(최대 512자), 미지 문자, 길이·마지막 패딩 비트 오류, 미지 버전/키 ID/플랜/기수, 발급일 미래 오차 초과, 기간 오류, 서명 오류는 거부한다.
- 시각은 UTC 초, 유한 만료 경계는 `now >= expires_at`. 월 납부의 12개월은 발급 UTC 날짜에 12개월을 더하고 해당 월에 날짜가 없으면 말일로 조정하며 시각을 유지한다. 무기한은 일시불에서만 허용하며 표시와 비교에서 별도 처리한다. 유한 날짜는 예약된 `0xffffffff` 미만만 사용한다. 일시불의 무기한/긴 기한 선택은 발급 전 Jake가 정한다.
- 요구된 `ilson license activate <시리얼>`도 지원하되 셸 히스토리·프로세스 목록에 노출될 수 있다. 기본 안내는 `ilson license activate` 후 숨김 붙여넣기, 비대화형은 `--stdin`이다. 전체 시리얼을 오류·상태·로그로 다시 출력하지 않는다.
- 서명 키는 2단계에서만 만든다. 디렉터리 0700·개인키 0600을 생성 시점부터 적용하고 소유권·일반 파일·링크 여부를 확인한다. 작업자는 직접 `chmod`·`sudo`·`chown`·`rm` 명령을 치지 않는다. `kid`를 통한 공개키 교체는 새 공개키 선배포·재발급·구키 폐기 계획을 따른다. 키 유출·분실 시 오프라인 기기가 즉시 폐기를 알 수 없으며 복구/백업은 Jake가 별도로 결정한다.

## 3. 활성화와 유예 상태

- 저장: `$ILSON_HOME/state/license/` (기본 `~/ilson/state/license/`, sandbox는 격리 경로). 디렉터리 0700, `serial`, `device-id`, `state.json` 0600. 생성부터 최소 권한, 소유자·일반 파일·심볼릭 링크 검사, 임시 파일 원자 교체 및 실패 시 기존 상태 보존. 재설치·업데이트·롤백에서 사용자 볼트와 라이선스를 보존한다.
- 최초 활성화: 서명·기간 검증 → 기기별 CSPRNG 256비트 `device_id` 생성 → 서버 활성화(연결 제한 3초, 전체 제한 5초 제안). 정상 승인 시 저장한다. 통신 장애 시 로컬 최초 활성화 시각을 고정하고 14일 유예한다. 잘못된 시리얼이나 서버의 명시적인 신규 기기 거절을 장애로 바꾸지 않는다. 최초 오프라인 활성화 시각은 보호된 로컬 상태에 남긴다. 저장 실패는 성공으로 표시하지 않는다. 재시도/동일 시리얼 재입력으로 시작점을 초기화하지 않는다.
- `device_id`는 하드웨어 ID·MAC·호스트명 대신 무작위 값이다. 서버에는 `SHA-256("ilson-device-v1\0" || device_id)`만 저장한다. 폴더 복사 시 동일 기기로 보이거나 재설치 시 새 기기로 보일 수 있다. 삭제·조작·시계 변경을 완전히 막을 수 없으므로 Jake의 기기 해제 복구를 둔다.
- 서버는 활성화 및 보호 기능 실행 시 **마지막 성공 확인 후 24시간마다** 기회적으로 확인한다. 별도 daemon은 만들지 않는다. 서버 복구 시 최초 오프라인 기기는 등록을 시도하고, 이미 등록된 기기는 상태를 확인한다. 웹과 예약 업무도 같은 정책을 쓴다. `ilson license status`는 마스킹 ID, 플랜, 서명 만료, 마지막 서버 확인, 확인된 `paid_until`, 유예 기한·사유를 표시하고 강제 재확인을 제공한다.
- **통신 장애 유예:** 최초 오프라인은 `min(서명 만료, 최초 오프라인 활성화 + 14일)`, 이후는 `min(서명 만료, 마지막 서버 승인 + 14일)`. 무기한 서명은 해당 min 항을 생략한다. 5xx·DNS·타임아웃·TLS 오류·잘못된 응답·429는 통신 실패이며 시작점을 갱신하지 않는다. 로컬 상태/시계를 삭제·조작하면 우회할 수 있는 소프트 잠금이다.
- **취소:** 서버에서 취소가 확인되면 즉시 잠근다. 오프라인에서는 취소를 알 수 없으므로 마지막 승인부터 최대 14일이며, 서명 만료가 더 빠르면 거기서 끝난다. 거절을 통신 장애로 처리하거나 재입력으로 유예를 초기화하지 않는다.
- **월 납부:** 서버의 `paid_until`은 배타적 UTC 시각이고 `server_time < paid_until`일 때 납부 유효하다. Jake가 서버의 날짜만 연장하며 기존 시리얼과 기기 등록은 유지한다. 온라인에서 `paid_until` 경과를 확인하면 `PAYMENT_DUE`로 잠그고 Jake 문의를 안내한다. 취소는 `revoked_at`이 있는 상태로 따로 표현한다. 통신 장애 중에는 마지막 승인 후 최대 14일(서명 만료 이내) 계속할 수 있어 마지막으로 받은 `paid_until`이 지나도 오프라인 사용이 가능하다. 서버 연결 시 납부 여부를 재판정한다. **매월 새 시리얼이나 Studio 서명이 필요하지 않다.** 12개월 서명 자체가 만료되면 유효기간 연장을 위한 새 시리얼은 필요하다.
- 유효하지 않은 서명·서명 만료·온라인 기기 한도 초과는 차단한다. 온라인에서 미납 또는 취소를 확인하면 즉시 차단한다. 마지막 정상 관측보다 5분 넘게 시계가 과거로 가면 날짜/시간 복구 및 온라인 확인을 안내한다. 인증된 서버 응답의 시각과 로컬 시각이 ±5분 이내임을 확인하면 CLOCK_ERROR를 해제하고 신뢰 기준을 갱신한다. 검사 중 이미 실행 중인 작업을 강제로 종료하지 않는다.
- `ilson license deactivate`는 서버 해제 성공 후 로컬 비활성화한다. 오프라인 해제는 성공했다고 표시하지 않고 Jake의 슬롯 해제를 안내한다. 로컬만 지우는 복구는 서버 슬롯이 남는다고 명확히 안내한다.

## 4. 잠금 범위와 실제 진입점

| 경로 | 무시리얼 또는 사용 불가일 때 | 적용 위치와 예외 |
|---|---|---|
| 설치, `setup/init`, `doctor`, 도움말, `ilson license` | 항상 허용 | 설치 마지막 시리얼 입력은 선택 사항. 실패와 다음 할 일을 통합 요약한다. |
| `chat`, `learn`, `research`, `motion`, `people`, `llm`, `pair`, `telegram connect`, `start`, `resume` 등 Box 명령 | 활성화 안내 후 차단 | 최상위 dispatch 전에 공통 검사; 개별 도움말은 허용. `pause`, `stop`, `admin stop/status`, `telegram status` 등 중지·진단은 허용. |
| 설치 중 기존 강의 키트 파일 생성 | **그대로 실행** | 6.2의 `init_step_box` 복사와 `install.sh` 마지막 키트 준비를 유지한다. 설치 전용 내부 경로와 사용자 명령을 구분하고 기존 파일을 덮지 않는다. 무시리얼도 생성 파일에 직접 접근할 수 있음을 명시한다. |
| `ilson course-kit`을 통한 갱신, 새 강의 키트·스킬 팩 받기 | 차단 | 활성화 후 명령으로 갱신. `chat` 등 키트를 사용하는 공식 명령도 차단. 공개 소스, 기존 파일, 외부 앱에서의 직접 읽기는 차단 불가. |
| `ilson update`, `--check`, `--feed`, 자동 업데이트 | 차단 | `tools/update.py` 및 launchd `template/lib/update.sh` 진입점 검사. 장애 복구용 `--rollback`은 허용하되 구버전 복귀 우회 가능. 공개 설치 스크립트 재실행도 소프트 잠금의 우회 경로다. |
| `open`, `admin start`, 웹 화면·API·정적 강의/팩 | **시리얼 입력 안내만** | 설치 과정에서 관리자 실행은 실패로 처리하지 않음. 잠긴 UI에는 활성화 명령 안내 및 필수 UI 자원만 제공, 기존 세션/직접 API·콘텐츠는 서버 측 차단. `admin status/stop`은 유지. 웹에서 입력 기능을 따로 만들지 않으며 CLI 활성화를 안내한다. |
| 기존 예약 업무 | 다음 실행부터 검사·건너뛰고 로그 | `run-job.sh`의 작업 실행 직전 검사. 무시리얼/사용 불가면 시리얼 없는 이유만 남기고 작업을 시작하지 않는다. 이미 실행 중인 업무와 기존 launchd 등록은 강제 중지·삭제하지 않는다. 안전/복구용 watchdog·snapshot은 유지, 자동 업데이트는 차단. 알림 폭주 방지. |
| 직접 스크립트, 공개 배포물, 기존 파일 | 공식 진입점에 가능한 검사 | 이미 열린 대화·수동 실행·파일 직접 열기는 완전히 막지 않는다. 전수 조사는 2단계에 한다. |

현재 `ilson`은 `course-kit`, `learn`, `update`, `motion`, `research` 등을 마지막 `case` 전에 별도 `if`/`exec`로 처리한다. `init_step_box`가 설치 시 키트를 직접 복사하고 `install.sh`도 마지막에 키트 명령을 호출한다. 자동 업데이트는 `template/lib/update.sh`, 웹은 `template/lib/web-admin-server.py`, 예약 업무는 `template/lib/run-job.sh` 경로다. 사용자 명령을 잠가도 설치 내부 복사가 정상 완료되도록 호출 분리를 설계한다. 실제 스케줄·웹·팩 직접 실행 경로는 구현 전 다시 검증한다.

## 5. 설치 마지막 통합 요약표

이번 판에 6.2의 누락을 보완한다. 설치 마지막에 **설치됨 / 실패 / 다음 할 일**을 한곳에 표시한다. 이는 새 2단계 구현 범위이며 아직 동작하지 않는다.

| 열 | 표시 기준 |
|---|---|
| 설치됨 | 실제 준비·재사용이 확인된 항목: 예를 들어 Box, 강의 키트, 도구별 결과, 웹 관리자. 이미 있던 도구는 재사용으로 구분한다. |
| 실패 | 실제 실패한 도구·설정별 이유와 재시도 방법. 부분 실패를 성공으로 묶지 않고 기존 종료 상태를 보존한다. |
| 다음 할 일 | 계정 로그인·필요한 권한·원격 연결·회사 인터뷰 등 확인되지 않은 항목과 선택 사항인 `ilson license activate`. 라이선스 미입력/서버 장애는 설치 실패가 아닌 별도 상태로 표시. |

키트 생성의 실제 결과와 라이선스 상태를 따로 표시한다. 요약은 일반/부분 실패/비대화형/재설치/sandbox에서도 실제로 도달 가능한 종료 경로에서 한 번 출력하고, 이전 단계가 실행되지 않은 항목은 ‘미확인/미실행’으로 표시한다. 설치 코드가 실행되기 전의 셸 오류까지 요약한다고 약속하지 않는다. 토큰·시리얼·사용자 입력은 요약이나 로그에 넣지 않는다.

## 6. Vercel API와 Supabase

HTTPS 전용 JSON, 최대 본문 8 KiB, `Cache-Control: no-store`, 요청/응답에 무작위 128비트 이상 nonce. 클라이언트가 보낸 nonce 불일치·응답 파싱 오류는 통신 실패다. TLS 검증을 끄지 않는다. 서버는 시리얼 서명·기간·프레임을 재검증하고 DB의 ID·필드·페이로드 해시와 대조한다. 전체 시리얼은 POST 본문에만 넣고 URL·로그·오류 추적에 넣지 않는다. 제공자 기본 로그·민감 헤더/본문 수집과 보관 정책을 배포 전 확인한다.

| API | 요청 | 성공·거절 |
|---|---|---|
| `POST /api/v1/activate` | `{serial, device_id, nonce}` | `{nonce,status,server_time,expires_at,paid_until,revoked_at,next_check_seconds}`. 상태와 기기 제한 판정 후 등록; 같은 기기는 멱등. 기기 한도 초과는 거절. 취소 시 기기를 등록하지 않고 취소 응답을 반환하며 온라인 기기를 즉시 잠근다. `expires_at`은 무기한 일시불에 null. |
| `POST /api/v1/check` | 동일 | 등록 기기에 서버 상태 반환. 오프라인 최초 활성화는 등록을 위해 activate. 취소 상태는 `revoked_at`을 포함한 정형 응답으로 알리고 즉시 잠근다. |
| `POST /api/v1/deactivate` | 동일 | 기기 슬롯 해제는 멱등. 취소 상태도 유효 서명·ID와 기기 확인 후 해제 가능. |
| `POST /api/v1/admin/*` | 관리자 비밀 + 요청 ID | 발급 기록 등록, 취소, 납부 기한 연장, 기기 목록/해제. Jake의 Studio 전용 관리자 비밀로 인증한다. 서버에서 비교하려면 같은 비밀 또는 검증값을 Vercel Secret으로 설정해야 한다. 사용자 기기·저장소에는 넣지 않는다. HTTPS·제한 속도·권한 검사·감사 로그를 적용한다. |

응답 `nonce`, `server_time`, 상태 및 예상 코드가 일치해야 한다. 구조가 맞는 `INVALID_SERIAL`, `EXPIRED`, `PAYMENT_DUE`, `DEVICE_LIMIT`, `DEVICE_NOT_REGISTERED`, `REVOKED` 등을 구분하고 알 수 없는 4xx/프록시 HTML을 정상 거절로 오인하지 않는다. `REVOKED`, `PAYMENT_DUE`, `DEVICE_LIMIT`는 확인 즉시 차단한다. 시간 오차 5분을 넘으면 `CLOCK_ERROR` 복구를 안내한다.

**스키마 제안** (전용 비공개 `license_private` 스키마):

- `licenses`: `id uuid PRIMARY KEY`, `payload_hash bytea UNIQUE NOT NULL` (SHA-256), `display_name text NOT NULL`, `cohort integer`, `plan` enum/check, `issued_at timestamptz`, `expires_at timestamptz NULL` (NULL은 일시불 무기한), `paid_until timestamptz NULL` (월 납부는 필수, 일시불은 NULL), `status` active/revoked, `revoked_at timestamptz NULL`, `device_limit integer DEFAULT 2 CHECK (device_limit > 0)`, `created_at`, `updated_at`. 상태·취소 시각의 일관성과 월납 기한을 CHECK로 강제한다. 표시 이름은 DB에만 보관한다. 원문 시리얼·연락처는 저장하지 않는다.
- `license_devices`: `license_id` FK, `device_hash bytea`, `activated_at`, `last_seen_at`, `released_at NULL`, 유일 `(license_id, device_hash)`. 활성 행만 기기 수에 포함. `licenses` 행을 `SELECT ... FOR UPDATE`로 잠근 **같은 트랜잭션**에서 상태/납부/만료/해시 검증 → 기기 수 확인 → 등록한다. 취소·납부 연장·해제도 같은 행 잠금 순서로 직렬화한다. 동시 3기기 요청과 멱등 재시도를 시험한다.
- `license_events`: 무작위 ID, license FK, 종류, 시각, 마스킹 기기 참조 또는 null, actor 종류, 요청 ID. 시리얼·개인키·관리자 비밀·본문·IP를 저장하지 않는다. 관리자 요청 ID 유일 제약 및 동일 ID/다른 내용 충돌 거절. 보관 기간·삭제 절차는 Jake가 확정한다.
- RLS를 켜고 `anon`/`authenticated`의 스키마·테이블·시퀀스·함수 접근을 명시적으로 REVOKE, 허용 정책 없음. 공개 Data API에 스키마를 노출하지 않는다. Vercel 서버에서 가능한 최소 권한 DB 역할과 제한된 트랜잭션 함수만 사용한다. Supabase secret/service role은 RLS를 **우회**하므로 서버 인가와 DB 권한 검사가 별도로 필요하다. SQL 매개변수 바인딩·고정 search_path 적용. 직접 DB 접속과 RPC 중 하나를 2단계에서 확정하고 권한·원자성 시험.
- Supabase의 rate limit 테이블과 원자적 트랜잭션으로 IP와 license ID 양쪽의 rate limit을 적용하고 관리자 API는 별도 제한한다. 원문 IP 장기 저장 금지. 제공자 인프라·비용과 실패 시 동작은 배포 전 확인한다.

## 7. 발급·취소·연장·관리자 복구

- Studio 전용 `server/license/` 발급/운영 CLI에 `issue`, `register`, `revoke`, `renew-payment`, `devices`, `release-device`를 제안한다. Jake만 서명·발급하고 발급 성공과 서버 등록을 각각 확인한다. 재시도 가능한 관리자 요청 ID를 보존하고 시리얼 자체는 서버에 저장하지 않는다. 안전한 전달·재발급 수단을 준비한다.
- Jake용 시리얼을 먼저 발급하고 Jake가 지정한 기기에서 직접 활성화·검증한다. 학생 4명에게 각각 다른 `license_id`와 서버 표시 이름·기수를 기록한다. 학생에게 보내는 일은 총괄이 Jake의 승인을 받은 뒤 수행한다. 직접 학생 기기나 macmini/macmini-1에 접근하지 않는다.
- 월납 `renew-payment`는 서명 기한을 변경하지 않고 `paid_until`만 증가시킨다. 잘못된 날짜·서명 만료를 넘는 표시 정책·중복 요청·동시 취소를 시험한다. 12개월이 끝나면 Jake가 새 서명 시리얼을 발급·등록해야 한다. 일시불 기한은 발급 전에 정한다.
- 취소 시 최초 `revoked_at`을 고정한다. 온라인 취소 확인 시 즉시 잠그며, 해제·취소 사실이 오프라인 기기에 즉시 전파되지는 않는다. 오프라인 기기는 마지막 승인 이후 최대 14일이다. 기기 분실 시 Jake가 슬롯을 해제하고 새 기기의 한도를 서버에서 확인한다.
- **관리자 비밀 복구:** Studio의 제한된 0600 로컬 보관본과 접근자를 Jake가 관리한다. 분실 시 기존 값을 알아내려 하지 않고 Jake 승인 후 Vercel Secret을 교체하고 새 배포에 반영, Studio의 보관본도 원자 교체한다. 교체 중 관리 API 실패와 기존 사용자 확인 API의 연속성을 시험한다. 유출이 의심되면 기존 비밀을 폐기·교체하고 관리 이벤트를 확인하며, 사용자 시리얼을 재발급할 필요가 있는지는 별도 조사한다. 서명 개인키 분실/유출은 관리자 비밀 교체와 별개로 키 교체·재발급 계획이 필요하다. 해당 외부 변경은 현재 승인·실행된 적 없다.

## 8. 개인정보·위협 모델

서버는 가명 표시 이름, 기수, 플랜, 발급·서명 만료·납부 기한·상태, 임의 기기 ID의 해시와 최소 운영 이력만 저장한다. 연락처·하드웨어 일련번호·MAC·호스트명·회사 볼트는 수집하지 않는다. 표시 이름은 시리얼에 없다. 삭제/정정 요청 경로, 백업·보관 기간, 서버 지역과 제공자 로그 보관은 실제 운영 전 Jake가 결정한다.

시리얼은 탈취되면 사용할 수 있는 bearer credential이다. TLS는 전송 중 보호, nonce는 응답 혼동·재전송 방지 보조일 뿐 탈취한 시리얼로 새 요청을 만드는 것을 막지 못한다. 서버의 기기 제한·취소·속도 제한으로 영향을 줄이되 공개 코드와 수정 가능한 로컬 상태는 보안 경계가 아니다. 사용자가 파일을 직접 열거나 구버전으로 돌아가는 것을 막지 못한다. 오프라인 중 취소를 모르는 기간의 사용 지속은 명시적으로 허용된 정책이다.

## 9. 사용자 메시지·강의 당일

| 상황 | 안내와 처리 |
|---|---|
| 설치 후 시리얼 없음 | `설치는 완료됐습니다. 일손을 사용하려면 ilson license activate를 실행해 주세요. 지금은 건너뛸 수 있습니다.` 강의 키트 파일 생성 결과는 요약표에 별도 표시. |
| 오타/서명 오류 | `시리얼을 확인하지 못했습니다. 전달받은 전체 내용을 다시 붙여넣어 주세요.` 기존 활성 상태 보존. |
| 최초 오프라인 또는 서버 장애 | `서버에 연결하지 못해 임시로 사용할 수 있습니다. YYYY-MM-DD HH:MM UTC까지 연결해 주세요.` 서명·기간 확인 후만 허용, 서버 복구 시 등록·한도 재판정. |
| 온라인 취소 확인 | `라이선스가 중지되었습니다. Jake에게 문의해 주세요.` 즉시 잠금. |
| 기기 한도 초과 | `등록 가능한 기기 수를 넘었습니다. Jake에게 기기 해제를 요청해 주세요.` |
| 미납 또는 유예 종료 | `납부 상태 또는 라이선스를 확인해 주세요. Jake에게 문의해 주세요.` 장애 유예 종료는 인터넷 연결·`ilson license status` 안내. |
| 서명 만료 | `라이선스 기간이 끝났습니다. Jake에게 새 시리얼을 요청해 주세요.` |
| 시계 오류/상태 저장 실패 | 날짜·시간 또는 파일/디스크 상태를 확인하도록 안내. 기존 상태를 임의 삭제하지 않는다. |

수업 전에 Jake와 학생별 시리얼을 준비하고 인터넷 없는 최초 활성화, 붙여넣기와 시계, 설치 요약을 검증한다. 수업 중 서버가 다운되면 유효한 서명으로 유예하고 오타는 재입력한다. 유효 시리얼이 없으면 Jake가 재발급한다. 시리얼 없이 보호 기능을 우회하는 만능 코드는 만들지 않는다.

## 10. 기존 설치·배포 순서

1. 6.2 병합 후 rebase 및 설치/업데이트/웹/예약 경로 재확인. 기존 사용자가 차단되므로 배포 전 Jake용 발급·안내·복구 경로 확보.
2. **총괄의 2단계 신호 이후에만** 코드·SQL·발급 CLI·격리 시험을 작성한다. 키 생성도 그때 Studio에서만 진행한다. 합성 시험 키와 격리된 임시 홈을 사용한다.
3. 독립 검토와 Jake 승인 후 총괄이 외부 프로젝트 생성·DB migration·Vercel 환경변수 설정·배포를 한다. 최초 오프라인 활성화와 설치 성공을 서버 미가용에서 확인한다.
4. Jake용 발급·등록·실기 활성화 확인 → 학생 4명 발급·등록 및 안전한 전달 준비 → 승인된 전달 → 점진적 릴리스. 기존 예약 업무를 삭제·강제 중지하지 않는다.
5. 기존 설치는 업데이트 후 시리얼을 활성화한다. 볼트·기존 키트·예약 설정을 보존한다. `ilson update --rollback` 복구는 허용하되 구버전·수동 설치 우회는 소프트 잠금의 한계다.

### Jake의 외부 작업 승인 목록 — 모두 미실행

- 콜드바이트 Vercel 프로젝트 생성·접근 권한과 서버 배포.
- Supabase 프로젝트·지역/요금/접근 권한, 테이블·인덱스·함수·RLS migration, 백업 및 보관 정책.
- API 도메인/DNS/TLS 또는 Vercel 기본 도메인 선택.
- Vercel 환경변수: Supabase URL(설정), 전용 DB 자격 또는 Supabase secret key(Secret), Studio 관리자 비밀의 서버 검증용 값(Secret), 필요시 rate-limit 저장소 자격(Secret). **발급용 Ed25519 개인 키는 Vercel에 넣지 않는다.** 관리자 비밀의 안전한 Studio 보관·교체도 승인 대상.
- 서비스 비용·로그 보관, 실제 발급 대상과 만료, 학생 전달, 실제 배포·릴리스. 외부 작업은 승인 후 총괄이 수행한다.

## 11. 시험 계획과 인수 기준 — 아직 실행 전

- 포맷: RFC 8032 벡터, 고정 프레임 길이·바이트 순서, 기수/플랜·발급일·무기한/12개월 만료 경계, 키 ID, 서명 변조·오타·공백/하이픈·Base32 패딩 비트, 붙여넣기, stdin/히스토리 노출. 이름이 시리얼에 없는지 검증한다.
- 상태: 최초 오프라인과 온라인→오프라인 14일 전후, 유한 서명 만료, 5xx/DNS/TLS/429/파손 응답, 온라인 취소 즉시 잠금, 오프라인 마지막 성공 확인부터 14일 전후, 서버 연결 후 취소 확인, 재입력/재시작으로 유예를 늘리지 않는지, 2대 초과, 기기 해제, 시간 후퇴, 저장 실패·링크·원자 교체. 기존 시리얼을 잘못된 입력으로 덮지 않는지 확인한다.
- 월납: 유효/미납 경계·서버 `paid_until` 연장 후 **동일 시리얼**로 복구, 오프라인에서 마지막 승인 14일 및 서명 만료 제한, 12개월 경과 후 새 시리얼 필요, 결제 연장/취소 동시성 및 중복 요청을 확인한다.
- API/DB: 서명/DB 해시 불일치, nonce 불일치, 관리자 권한·비밀 교체, 멱등 재시도, **동시 3기기 등록의 2대 제한**, 행 잠금, SQL injection, RLS 및 anon/authenticated 접근 실패, 비밀·본문 로그 유출 검증. 실제 PostgreSQL의 독립 트랜잭션으로 경쟁을 재현한다.
- 설치/제품: 합성 HOME의 새 설치·재설치·비대화형·오프라인에서 6.2 키트가 그대로 생성되고 파일을 보존하는지, 설치 마지막 통합 요약의 성공/실패/미실행과 실제 종료 코드, 무시리얼 공식 명령·웹/API·예약·자동 업데이트 차단 및 로그, 도움말/중지/복구/rollback 허용, 기존 볼트·예약·라이선스 보존, 실행 중 작업 비종료를 확인한다.
- 운영 인수: 서명 라이브러리의 실제 macOS 의존성, 수업용 기기, 온라인/비행기 모드, 전체 시리얼 입력 및 관리자 비밀 복구를 확인한다. 실제 배포·학생 접속·외부 서비스 검증은 승인과 실제 결과가 있기 전에는 성공으로 주장하지 않는다.

## 12. 검토 반영 및 MVP 범위

Antigravity 검토와 총괄의 2단계 지시(2026-11-06)에 따라 MVP를 확정한다.

- 시리얼에 이름을 넣지 않고 월 납부는 `paid_until` DB 변경으로 연장한다. 6.2의 키트 생성을 유지하고 설치 통합 요약을 추가한다.
- `template/lib/license.py`에 Python 표준 라이브러리 기반 Ed25519를 구현하며 RFC 8032 벡터를 시험한다. `tools/update.py` 배포 허용 경로와 설치 경로를 검증한다. 순수 Python 암호 구현은 외부 보안 감사를 받지 않았으므로 독립 시험과 코드 검토가 필수다.
- `snapshot.sh`에서 `state/license/`를 ignore하고 이미 추적된 경우 실패시키며, 실제 snapshot에서 시리얼과 기기 정보가 누출되지 않도록 시험한다. 웹 redact에 시리얼 패턴을 추가한다.
- 무라이선스 웹은 안내 화면만 보이고 백그라운드 워커도 검사한다. 무라이선스 예약 작업은 다음 실행부터 건너뛰고, watchdog의 미실행 알림은 억제한다.
- 온라인 취소는 즉시 잠그며 오프라인만 마지막 확인부터 최대 14일이다. 신뢰된 서버 시각과 로컬 시각이 ±5분 이내면 CLOCK_ERROR를 해제한다.
- rate limit은 Supabase 테이블로 처리한다. Vercel 기본 도메인과 Supabase 서울 지역 배포 절차를 준비한다.
- 강의 뒤 범위: 웹 시리얼 입력 UI, 키 교체 자동화, 외부 KV, 커스텀 도메인, 짧은 활성화 코드. 긴 시리얼은 붙여넣기로 입력한다.
- 외부 리소스 생성·배포·실제 키 생성이나 실제 사용은 하지 않는다. 시험용 키와 로컬/시험 DB만 사용한다.
