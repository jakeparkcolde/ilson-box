# Figure briefs — v06 예약 요청 보내 보기 (심화 6강)

Common rules: SPEC §8a and `FIGURE-STYLE.md` (SVG only, viewBox width 720, height ≤ 480, light plate `#f5f6f6`, palette tokens, Korean font stack, ≤ ~12 words per label, no logos, no browser brand marks — "개인 창" is drawn as a generic window with a darker top bar, not Safari's UI). Every text at least 18px at the 720 design width (main labels 20–24px). Code and error codes in mono 18–20px. Placeholders are never drawn. Never draw a real name, phone number, project URL or key value; practice values are 「연습 손님」 / 「연습 연락처」. **Keep a clear zone of about 120 × 72 px in the bottom-right corner of every figure (zoom badge).**

Our own image: the 돌다리 from basic lesson 7 — after the send works, the reader "knocks" on reading and must hear 42501. Draw it as plain cards and arrows (no stepping-stone illustration needed; if used, keep it a simple row of three flat rounded stones, no water drawing).

Colour meaning in this lesson: green = expected result (saved; and also 42501 on the read test, because refusal is what we want); red = what must never happen (the code mistakes in the comparison; a visible list on the read test); purple = what the reader does.
