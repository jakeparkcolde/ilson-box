# 반복 업무 스킬 제안과 승인형 학습 — 설계안

- 작성: 2026-11-06 · 상태: **총괄 구현 승인·Antigravity 설계 검토 의견 반영**, 구현 검수 대기
- 대상: `feat/autoskill-selflearn-20261106`, 기준 `163d732` (v2026.11.5.2)
- 결정: Jake, 반복 업무 2회 이상에서 스킬을 제안하고 학습·개선안을 만들되 **사람이 승인해야 스킬과 기준에 반영**한다. 11/9 강의 전 최소 기능을 목표로 한다.

## 1. 현재 확인한 경계

`ilson chat`은 `research/settings.py`에서 `ILSON_HOME`을 작업 폴더로 설정하고 Claude 또는 Codex를 실행한다. Codex에는 Box `CLAUDE.md`를 먼저 읽으라는 시작 프롬프트가 있다. 기본 `CLAUDE.md`는 `vault/lessons/`를 업무 전에 읽도록 지시한다. 기존 실행 중 세션에 새 지침이 자동 적용되는 것은 아니다.

예약 업무는 별도 `run-job.sh`, `job-rules.md`, `job-settings.json`을 쓰고 Claude의 설정·훅·스킬 상속을 끈다. `job-rules.md`가 볼트와 lessons 읽기를 직접 지시하지만, 예약 실행이 대화형 스킬을 자동 발견한다고 보장할 수 없다. 직원 화면의 스킬은 `.workspace/work.sqlite3`의 순수 텍스트 지침이며 파일 기반 Claude 스킬과 별개다. 기존 직원 스킬 화면에 자동 등록하거나 정기 업무에 자동 배정하지 않는다.

`ilson setup`은 vault 기존 파일을 보존하나 현재 `CLAUDE.md`와 배포 템플릿을 복사한다. `update.py`는 vault/state/logs를 배포 대상에서 제외하고 관리 파일의 사용자 변경을 검사해 충돌 시 중단한다. `snapshot.sh`는 vault/state를 로컬 Git에 남긴다. 따라서 vault에 저장된 초안도 로컬 Git 이력에 남을 수 있다. 삭제가 과거 이력의 완전 삭제를 뜻하지 않는다.

11/5 점검은 로컬 관리자와 외부 AI 처리의 경계를 구분했다. 이 설계의 저장·판단은 로컬에서 하지만 이미 대화에 입력되거나 AI가 읽은 자료는 Claude/Codex 제공자에게 전달될 수 있다. 기존 텔레그램·로그 관련 점검 사항도 이 기능이 해결했다고 주장하지 않는다. 강의는 가상 자료와 미연결 계정으로 한다.

## 2. 사용자 경험과 승인

1. 기본은 **수집 꺼짐**. 최초 안내에서 무엇을 기록하는지, 로컬 Git 스냅샷 가능성, 대화의 외부 모델 처리, 중지 방법을 설명하고 사용자가 수집을 켠다. 기존 대화·로그·문서·스킬은 소급 수집하지 않는다. `ilson learn status|enable|disable`로 상태 확인·명시적 전환을 제공한다.
2. 활성화된 `ilson chat`에서 업무가 끝나면 AI가 완성된 업무인지 확인하고, 아래 허용된 분류값과 개인정보 검사에 통과한 40자 이하의 짧은 업무 이름을 로컬 도우미에 보낸다. 작업 본문·대화 원문·로그·파일 경로는 저장하지 않는다. 자동 기록은 지침에 따른 **최선 노력**이며 모델의 누락/오분류가 가능하다. 사용자 또는 AI가 `ilson learn record`의 안내형 입력으로 보정할 수 있다. 같은 업무의 수정·재시도는 1회다.
3. 서로 다른 완료 업무 두 건이 같은 분류와 비슷한 업무 이름에 해당하거나 사용자가 동일 업무라고 확인하면 즉시 대화에서 “이 작업을 스킬로 만들까요?”와 검토 경로를 보여준다. 로컬 큐에는 제안 초안만 둔다. AI가 표시를 놓친 경우 `ilson learn proposals`로 확인할 수 있다. 생성은 저장 승인이나 실행 승인이 아니다.
4. 사람은 일반 터미널에서 `ilson learn show <id>`로 전체 초안 또는 unified diff, 출처 범주, 대상 경로, 주의사항을 읽고 `ilson learn approve <id>` 또는 `ilson learn reject <id>`를 직접 실행한다. 대화에서 “승인할까요?”라고 말한 것만으로 반영하지 않는다. 이 명령은 상호작용 TTY와 명시적 확인 문구 입력을 요구하고 비대화형 호출을 거부한다. 모델 지침에는 이 승인·거절·복구 명령을 대신 실행하지 말라고 명시한다. **동일 OS 사용자 권한을 가진 프로그램을 구분하는 보안 경계는 아니며** TTY만으로 사람이 입력했음을 암호학적으로 증명하지 않는다.
5. 승인 시에만 사용자 스킬이나 활성 기준 문서를 만든다/변경한다. 거절 억제 키는 `(kind, output, workflow, 정규화한 업무 이름)`이며 이 키의 제안을 자동으로 다시 만들지 않는다. 사용자가 `ilson learn reconsider <id>`를 직접 명시하기 전까지 유지한다. 수정해서 재제안하기, 기록 중지와 재개는 명시적으로 할 수 있다.

여기서 수집 허용은 **검사된 업무 이름·분류 이벤트와 미승인 초안의 로컬 저장**에 대한 동의다. 스킬 설치, 기준 반영, 외부 발송에 대한 동의가 아니다. 제안 큐를 저장하지 않는 해석이 필요하다면 이 설계는 Jake 결정과 다르므로 구현 전에 총괄이 반려한다. 텔레그램 등으로 이 기능의 기록·제안을 보내는 경로는 없고 기본 꺼짐이며 설정을 켜도 MVP에서는 발송하지 않는다.

## 3. 동일 업무와 이벤트 계약

- 이벤트는 `event_id`(임의 UUID), 독립 요청(업무 완결 건)별 고유 `task_id`, 시각(UTC), 공급자(`claude|codex|manual`), `kind`, `output`, `workflow`의 **고정 선택값**과 검사된 40자 이하 업무 이름만 담는다. 대화 원문·로그·경로·원문 해시는 담지 않는다. AI와 사용자는 사람·회사·연락처 등 식별 정보를 이름에 넣지 않는다. UUID는 내용에서 유도하지 않는다. 한 `task_id`는 한 번만 센다. 같은 대화 세션의 서로 독립된 요청도 각각 새 ID를 쓴다. 변경·재시도는 같은 ID, 독립된 새 요청은 새 ID를 사용한다. 중복 이벤트 저장도 멱등이다.
- MVP 분류 예: `kind=document|research|summary`, `output=report|checklist|draft`, `workflow=organize|verify|summarize` (지원 조합만 허용). **세 값 모두 일치**하고 짧은 업무 이름의 로컬 정규화 문자열 유사도가 0.85 이상인 독립 완료 업무 2건 이상을 같은 후보로 본다. 대소문자·유니코드·공백과 구두점을 정규화하고 `difflib.SequenceMatcher`로 비교한다. 또는 사람이 명시적으로 두 건을 동일 업무로 확인하면 이름이나 분류가 달라도 같은 후보로 묶는다. 거절 억제 키에는 두 번째 업무의 분류와 이름을 쓴다. 폴더·기존 스킬 사용은 판단에 쓰지 않는다. 오분류가 가능하므로 제안에 두 건의 날짜와 업무 이름·분류를 보여주고 사람이 확인한다. 지원하지 않는 업무는 억지로 분류하지 않고 기록하지 않는다.
- 이벤트는 완료 시에만 센다. 실패는 반복 횟수에 넣지 않고 아래 배운 점 사건으로 별도 분류한다. 분류 결정·ID 전달이 안 됐으면 감지 보장이라고 표시하지 않는다. CLI는 스키마 외 키, 이름과 초안을 제외한 자유 문자열, 지나친 크기와 잘못된 조합을 저장 전에 거절하고 입력을 오류/로그에 재출력하지 않는다.
- 두 번째 업무의 현재 대화에서 AI가 사용자 앞에 실제 맥락과 검증된 업무 노하우를 일반화해 스킬 초안을 만든다. `name`, `description`(언제 쓰는지), 입력, 단계별 순서, 품질 기준, 결과물, 사람 확인 및 실패 시 중단을 포함한다. 미상 정보는 추정하지 않고 `[확인 필요]`로 둔다. 개인식별정보·비밀·고객 원문은 제외하고 본문을 표준 입력으로 도우미에 넘긴다. 검사 통과 시에만 미승인 큐에 저장한다. 초안 미제공 시 7개 항목의 기본 템플릿으로 대체한다. 대화 원문·로그는 저장하지 않는다.

## 4. 배운 점과 변경안

- 작업 중 사용자의 수정, 실패, 잘된 방식은 `correction|failure|success`와 고정 선택값인 `issue` 및 `action`을 같은 도우미로 기록한다. 예: `correction/unsupported_claim/check_evidence`, `failure/missing_input/ask_before_work`, `success/source_check/keep_sources`. 이 분류에 현재 대화에서 추출한 1~2문장·160자 이하 일반화 기준을 선택적으로 붙일 수 있다. 개인정보·비밀·권한 확대를 검사하고 실패 시 저장하지 않는다. 문구가 없으면 조합별 고정 문구를 사용한다. 허용 조합 이외는 수집하지 않고 사용자가 직접 확인해 적절한 분류를 선택할 수 있다. 기록은 활성화한 경우에만 하고 원문·사유·고객 정보는 남기지 않는다.
- 작업 종료 시 로컬 규칙으로 미처리 사건을 평가한다. 하루가 지나도 이용 중이었다면 다음 `ilson chat` 시작 또는 `ilson learn review`에서 한 번 더 평가한다. 새 LaunchAgent·상시 감시·자정 기상은 없다. `review`는 idempotent이며 중복 초안을 만들지 않는다. 해당 분류가 현재 기준에 이미 있거나 미지원이면 자동 변경안을 만들지 않는다.
- 학습 제안은 활성 기준 `vault/lessons/approved-learning.md`에 검사를 통과한 일반화 문구 또는 고정 문구 한 항목을 추가하는 **unified diff**다. 스킬 변경 제안은 이 버전에는 추가하지 않으며 이후 확장한다. 직접 `CLAUDE.md`/`AGENTS.md`를 AI가 덮어쓰지 않는다. 배포 `CLAUDE.md` 및 예약 `job-rules.md`는 기존 lessons 읽기 계약을 더 명확히 하고, 다음 대화의 Claude와 Codex 시작 경로가 승인된 이 문서를 읽도록 안내한다. 예약 업무는 기존 `job-rules.md`의 Read만 이용한다. 사람이 변경한 다른 lessons도 존중하고 새 기준은 최신 사용자 지시·권한·안전 규칙보다 우선하지 않는다.
- 승인 시 최초 대상 부재면 새 파일, 존재하면 **제안 작성 시와 승인 직전의 SHA-256**이 같을 때에만 정확한 전체 diff를 적용한다. 불일치하면 양쪽을 그대로 두고 충돌로 표시해 재검토한다. 최초 파일에도 이미 존재하는 경우를 충돌로 다룬다. 거절은 활성 기준을 수정하지 않는다. 제안이 외부 자료를 권한 또는 승인으로 취급하는 내용이나 보안 규칙 완화를 포함하면 생성·반영하지 않는다.
- 변경 이력에는 임의 변경 ID, 승인 시각, 대상의 상대 경로, 이전/이후 SHA-256과 승인된 diff, 복구용 이전 버전을 vault 안에 둔다. `ilson learn history`와 `ilson learn rollback <id>`는 내용을 먼저 보여 주고 사람의 별도 확인을 요구한다. 현재 파일이 해당 변경의 이후 해시와 일치할 때만 복구한다. 나중에 사람이 바꿨거나 다른 승인이 적용됐으면 덮어쓰지 않고 충돌을 보고한다. 신규 스킬 복구도 설치 이후 수정이 없어야 하며, 안전한 보관 위치로 이동해 비활성화한다. 복구 기록도 남긴다.

## 5. 저장 위치, 트랜잭션, 보안

| 내용 | 위치 | 성격 |
|---|---|---|
| 수집 설정, 분류 이벤트, 거절 상태, 초안, 이력·이전본 | `vault/.ilson-learning/` | 로컬 데이터. 비승인 초안은 활성 지침이 아님. 제한된 권한, 크기·건수 제한 |
| 승인된 학습 기준 | `vault/lessons/approved-learning.md` | Box 기존 lessons 읽기 경로. 사용자 파일 |
| 승인한 파일 스킬 | `.claude/skills/ilson-learned-<랜덤ID>/SKILL.md` | 프로젝트 로컬 사용자 파일. 사용자 선택·승인된 내용만 |
| 승인된 스킬의 읽기 목록 | `vault/.ilson-learning/approved-skills.json` | 상대 경로·해시만. Codex는 목록을 읽고 해당 업무에 맞는 스킬 본문을 명시적으로 읽음 |

스킬 디렉터리 충돌 시 새로 만들지 않으며, 설치 관리 템플릿명과 겹치지 않는 이름을 쓴다. Claude에서는 새 세션의 프로젝트 스킬 경로에 둔다. Codex에는 `.agents/skills` 자동 발견을 주장하지 않고 `ilson chat` 시작 지침에서 위 목록과 `.claude/skills/.../SKILL.md`를 명시적으로 읽도록 한다. 목록에 없거나 해시가 달라진 파일은 자동 실행하지 않고 사용자에게 변경 확인을 요청한다. 사람이 직접 고친 파일을 덮어쓰지 않는다. 이는 AI가 지침을 따르는 경로이며 모델의 실제 준수를 강제하는 격리는 아니다. 이미 열린 세션은 새로 시작하거나 지침을 다시 읽어야 한다.

스킬 초안은 현재 대화에서 AI가 작성한 맥락 기반 일반화 문장이다. 학습 기준 diff도 검사한 일반화 문구(미제공 시 고정 문구)를 쓴다. 이름과 스킬 초안은 저장 전 검사하고, 첨부물·대화 원문·로그를 저장하지 않으며 CLI 인자에는 민감한 원문을 넣지 않는다. 초안/활성 문서에 대해서도 이메일·전화번호·주민번호·계좌·키·토큰·비밀번호와 `check_public.py`에 대응하는 알려진 비밀 패턴(계좌 판정에서 YYYY-MM-DD 제외) 등을 검사하고 탐지 시 마스킹 대신 저장·반영을 거부한다. 검사 결과는 종류만 표시한다. 허용 목록 밖 구조 거부와 AI의 식별정보 제거가 1차 보호이며, 이름이나 자유 문장 안의 모든 개인정보·비밀을 패턴만으로 식별할 수 있다고 주장하지 않는다. 사람도 미승인 초안을 검토해야 한다. 기존 템플릿의 문구는 합성 데이터로 점검한다. 제안은 순수 Markdown만 허용하고 스크립트, 훅, 도구 설정, 외부 발송·네트워크 호출, 명령 실행과 권한 확대를 넣지 않는다.

모든 경로는 지정된 Box 기준 상대 경로만 허용하고 `..`, 절대 경로, 심볼릭 링크 및 Box 밖으로 벗어나는 경로를 거절한다. 쓰기 전 소유자·일반 파일 여부 및 부모를 검사하고 동일 디렉터리 임시 파일, fsync, 원자 교체를 사용한다. 승인·복구에는 Box별 잠금과 내용 해시 재검사를 적용한다. 스킬 파일, 목록, 이력처럼 여러 파일에 걸친 변경은 의도·이전/이후 해시가 있는 vault 내 저널을 먼저 확정하고, 중단 시 자동으로 미완료 상태를 인지해 해시가 일치하는 부분만 복구하거나 충돌로 멈춘다. 불명 상태에서 중복 반영하지 않는다. 실행 입력·민감값을 로그나 오류로 출력하지 않는다. vault와 스킬은 이 기능에서 네트워크로 보내지 않는다.

`update.py`의 vault 금지 규칙은 유지한다. `update.py allowed()`에서 `.claude/skills/ilson-learned-*`를 명시적으로 제외한다. 공식 CLAUDE.md·기본 스킬의 배포 소유 해시 목록을 포함해 업데이트 이력이 없는 tar.gz 설치도 판별한다. 배포물에는 프로그램·템플릿만 넣고 사용자 학습 파일과 만들어진 스킬은 싣지 않는다. 새 설치와 기존 설치 각각 설치/업데이트/재설치 시험을 한다. 현재 `setup`의 관리 파일 무조건 복사 때문에 사용자가 고친 `CLAUDE.md` 또는 이름이 겹치는 기본 스킬이 덮이지 않도록 소유 버전 확인 및 충돌 시 보존·안내를 구현한다. `update.py`의 기존 사용자 변경 충돌을 우회하지 않는다. 충돌로 새 지침이 설치되지 않았다면 기능 준비 미완료로 표시하고 안전하게 수동 검토를 안내한다. 사용자가 만든 `ilson-learned-*`는 배포 관리 목록에서 제외해 설치와 업데이트 양쪽에서 보존한다. 잠금·임시 파일은 로컬 `.gitignore`로 제외하고, 로컬 Git 스냅샷은 비밀 저장소가 아니며 백업 정책과 삭제 이력 제한을 안내한다.

## 6. 성능·비용·지원 범위

- 자동 분류 보조·2회 판단·기준 diff 생성·하루 점검은 Python 표준 라이브러리의 로컬 규칙 처리: **추가 LLM 호출 0회/업무, 0회/일**. 스킬 초안은 현재 대화의 AI가 작성하므로 대화 토큰은 추가로 쓰지만 별도 모델 호출은 없다. 별도 서버·상시 스캐너·추가 의존성·외부 요청 없음. 기존 대화 모델의 응답 토큰과 사용량은 발생할 수 있고 기존 구독/제공자 조건에 따른다.
- 크기 제한: 이벤트 최대 1만 건, 미승인 제안 200건, 제안 및 활성 기준 각각 24KB. 한도를 넘으면 기존 데이터를 삭제하지 않고 기록을 중단해 안내한다. 데이터 삭제·보존기간 설정과 과거 Git 이력 정리는 추후 별도 설계한다.
- `ilson chat`에서 Claude와 Codex 모두 같은 지침·도우미·큐를 사용하도록 설계한다. 두 공급자 모두에 대해 별도 통합 시험이 통과해야 지원으로 표시한다. 일반 독립 `claude`/`codex`나 외부 프로젝트, 직원 직접 업무, 예약 업무의 자동 감지는 MVP 범위 밖이다. 예약 업무는 `vault/.ilson-learning/**`와 `vault/lessons/approved-learning.md`의 Edit/Write를 명시적으로 거부하고, 미승인 초안의 읽기·직접 수정을 금지한다. 예약 업무의 승인된 lessons 읽기는 기존 명시적 경로를 유지하되 실제 모델 준수와 새 맥 실기는 별도 시험 전 미검증으로 표시한다.

## 7. 강의 실습과 수용 기준

본교재 47장 「반복 업무를 스킬로」와 7블록의 트리거·순서·사람 확인·완료 증거·실패 시 중단에 맞춰 가상의 동일한 문서 정리 업무를 서로 독립된 요청으로 두 번 수행한다. 실습 전 수집을 켜고 완료 분류가 기록됐는지 확인한다. 2회 뒤 초안에서 언제 쓰는지·입력·순서·품질·결과·확인·중단을 검토한다. 사람이 승인하면 파일 생성과 다음 새 대화의 읽기 경로를 확인한다. 별도의 가상 수정 지시를 분류해 diff를 확인한 뒤 승인, 이력, 되돌리기를 시연한다. 거절과 미승인은 활성 파일이 생기지 않는다는 예도 포함한다. 자동 분류가 누락되면 안내형 수동 기록을 사용하고 이를 자동 감지 성공으로 발표하지 않는다. 텔레그램 연결·실제 고객 정보·실제 예약 발행은 요구하지 않는다. 직원 스킬/정기 예약 연결과 파일 스킬을 구분한다.

필수 시험은 격리 HOME/Box와 가짜 공급자만 사용한다. (1) 두 독립 ID에서 1개 제안, 중복·한 작업 재시도·분류 불일치·실패 제외, (2) 직접 승인 전 무반영, 승인 생성, 거절 영구 억제와 명시 재검토, (3) 세 유형 사건과 일/작업 종료 점검의 diff 생성·중복 방지, (4) 승인·이력·복구·충돌·중단 복구, (5) 비밀/PII 패턴·예상 밖 필드·경로/링크/동시성 거부와 로그 누출 방지, (6) 사용자가 고친 파일 보존, (7) 새 설치·기존 설치·재설치·업데이트·배포 rollback 이후 vault/스킬 보존 및 업데이트 충돌, (8) Claude/Codex 시작 지침·예약 권한 및 외부 발송 부재다. 실제 사람의 승인 명령과 가짜 공급자 흐름을 분리해 시험한다. 전체 테스트는 병렬 실행하고 stdin은 DEVNULL로 둔다. 릴리스 조립과 공개 검사도 실행하되 게시하지 않는다. 실제 모델의 자동 기록 및 실기 결과는 별도 검증 여부를 적는다.

## 8. 11/9 최소 범위와 이후

**최소 범위:** 명시적 수집 동의, 대화 종료 시 최선 노력 분류와 수동 보정, 2회 제안·현재 대화의 맥락을 반영한 AI 초안, CLI 검토/승인/거절, 승인 스킬과 Codex 명시적 읽기, 학습 사건과 기준 diff·승인·이력·충돌 안전 복구, 설치/업데이트 보존, 문서와 위 시험. 웹 관리자 변경 없이 CLI를 정식 승인 화면으로 삼는다.

**이후:** 의미 기반 유사도·고급 개인정보 감지와 초안 품질 향상, 웹 승인 UI, 사용자가 수정한 스킬에 대한 diff, 직원 스킬 연동, 정기업무의 관찰과 스킬 적용, 알림, 보존기간/삭제와 Git 이력 처리, 독립 세션·여러 기기 동기화. 이들은 프라이버시·권한·비용·승인을 다시 설계하기 전에는 동작하지 않는다.
