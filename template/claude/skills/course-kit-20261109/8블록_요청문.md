# 8블록 요청문

> 부교재 v2.9 · 확인일 2026-11-05

**실제 기록 기반 새 요청문 · 미실행** — 당시 Jake 발언·AI의 원문 요청이 아닙니다.

실습할 때는 첫 줄의 사례 이름(예: 반짝 물 1편·깃밥쿠커)을 [내 가게/업무 자료]로 바꾸고 내 자료를 아래에 함께 붙여 넣으세요.

## 1블록 · 목표와 업무 흐름

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
실제 안부 초안 요청 3건으로 오늘 끝낼 작은 결과를 정해 주세요. 입력→작업→사람 확인→결과를 쓰고, 발송 전 검토 메모까지로 범위를 정해 주세요.
```

## 2블록 · 자료와 설계

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
반짝 물 1편의 PLAN.md와 STANDARD.md 가림 사본에서 목표·자료·문안·그림 기준·사람이 고를 것을 정리해 주세요. 문서에 없는 완료 사실은 확인 필요로 두세요.
```

## 3블록 · 역할과 작업 분리

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
깃밥쿠커 Archify 기록에서 자료 조사·제작·독립 검토·Jake가 각각 한 일을 나눠 주세요. 각 단계가 받은 입력, 남긴 결과, 다음 사람에게 넘긴 기준을 표시해 주세요.
```

## 4블록 · 수정과 이어가기

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
반짝 1편의 첫 인물 그림과 재생성 기록을 대조해 한 가지 수정 이유를 적어 주세요. 바꾼 것·유지한 것·다음에도 읽을 기준을 실제 기록으로 이어가기 메모에 남겨 주세요.
```

## 5블록 · 채널별 초안과 승인

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
반짝 물 1편의 실제 문안과 채널 기준을 읽고, 유지할 사실과 Instagram·Threads의 말투·길이 차이를 정리해 주세요. 제목·본문·다음 행동·게시 전 확인 항목을 함께 써 주세요.
```

## 6블록 · 개선 제안

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
깃밥 기획에서 초보자가 도구 설명을 이해하기 어려운 문제를 찾아 주세요. 도구 유형·준비물·용어 풀이 중 오늘 보강할 하나와 나중에 만들 기능, 확인 방법을 구분해 주세요.
```

## 7블록 · 반복 업무 설계

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
깃밥쿠커의 실제 제작·승인 기록을 읽고 다음에도 반복할 시작 자료·작업 순서·사람 확인·완료 증거·멈출 조건을 적어 주세요. 미공개 다음 회차나 자동 발행 성공은 만들지 마세요.
```

## 8블록 · 완성·검증

```text
깃밥쿠커 Archify v4c 기록에서 목표·수정·검사·Jake 승인을 구분해 주세요. 확인한 결과와 공개 파일 동일성·자동 게시 시각처럼 확인 못 한 항목을 나눠 최종 검토표를 만들어 주세요.
```

## 한 번에 따라 보기 · 실제 업무 기록 기반 가림 사본

원래는 거래처 한 곳씩 이름·마지막 주문 경과일·작성 규칙을 넣어 안부 카톡 초안을 요청한 기록입니다.

세 건은 실제 주문전표나 고객 문의가 아니라, 2026-10-12 운영 자동화가 AI에 넣은 **거래처 안부 초안 작성 요청 3건**입니다. 고객 A·B·C는 실제 거래처의 가명입니다. Jake가 직접 타이핑한 대화로 소개하지 않습니다.

### 1. 입력 · 실제 요청 3건의 가림 사본

```text
실제 업무 기록 기반 · 개인정보를 가린 사본

업무: 한동안 주문이 없는 거래처 사장님께 보낼 안부 메시지 초안을 준비한다.
입력: 고객 A·B·C의 안부 초안 요청과 공통 작성 규칙.
공통 규칙: 사장님이라는 호칭, 정중한 말투, 부담 없는 안부.
가격·할인·프로모션·거래 조건은 임의로 약속하지 않는다.
내부 분석 용어나 수치를 메시지에 쓰지 않는다.
원기록의 마지막 주문 경과일: 고객 A는 값 없음, 고객 B·C는 (가림).
결과: 원자료에서 확인되는 사실과 확인할 내용을 나눈 발송 전 검토 메모.
```

| 확인 대상 | 실제 입력의 상태 | 검토할 내용 |
|---|---|---|
| 고객 A | 마지막 주문 경과일 값 없음 | 구체적인 날짜를 만들지 않는다. |
| 고객 B | 마지막 주문 경과일 (가림) | 입력에 없는 거래 관계·혜택을 덧붙이지 않는다. |
| 고객 C | 마지막 주문 경과일 (가림) | 매장에서 취급하는 품목·관계를 확인 없이 단정하지 않는다. |

이 표는 원기록을 정리한 새 검토 메모이며 당시 AI가 출력한 표는 아닙니다. 실제 발송 결과·고객의 답·매출 효과는 근거 없음.

### 2. 채운 새 요청문 · 미실행 초안

```text
위 실제 업무 기록 기반 사본을 읽고, 고객 A·B·C별로 확인된 사실과 확인할 내용을 표로 정리해 주세요.
고객 A의 마지막 주문 경과일은 값 없음으로 두고 날짜를 만들지 마세요.
안부 초안을 검토할 때 입력에 없는 거래 관계, 품목, 가격·할인 약속이 들어갔는지 찾아 주세요.
내가 확인할 질문을 남기고 발송 전 검토 메모까지만 만들어 주세요.
```

### 3. 당시 실제 AI 답변 일부 · 고객 B

```text
요즘 뜸하셔서 궁금했습니다. 오래 거래해온 사이라 더 신경 쓰이네요. 매장 운영하시면서 필요하신 부분 있으시면 편하게 말씀 주세요.
```

실제로 오래 거래했더라도 입력 자료에 안 적은 말을 AI가 추측해 넣었으므로 사람이 확인해야 합니다.

### 4. 사람 확인 · 이번 강의용 검토 의견

```text
확인한 문제: 입력에 없는 ‘오래 거래해온 사이라’가 답변에 들어갔다.
고칠 부분: 이 문장을 빼고도 안부와 연락 안내가 이어지는지 본다.
확인할 질문: 실제로 오랫동안 거래한 관계라는 근거가 있는가?
현재 상태: 원문 답변은 확보했다. 당시 이 표현을 실제로 고쳐 발송했는지는 근거 없음.
```

**삭제만 적용한 수정 제안 — 당시 수정본이 아님**

```text
요즘 뜸하셔서 궁금했습니다. 매장 운영하시면서 필요하신 부분 있으시면 편하게 말씀 주세요.
```

**실제 요청의 작성 규칙 발췌**

```text
- 호칭: "사장님". 정중한 경어체.
- **가격·할인·프로모션·조건 제시 절대 금지** (승인 전 임의 약속 불가).
- 사업자번호·금액·점수 등 내부 수치 언급 금지.
```

위 세 줄은 같은 요청의 떨어진 항목을 골라 발췌했습니다. 원래 요청 전문이나 연속된 세 줄이라고 표시하지 않습니다.

### 5. 오늘의 결과

```text
입력: 실제 안부 초안 요청 3건 → 작업: 사실·누락·초안 대조 → 사람 확인: 근거 없는 표현과 임의 약속 확인 → 결과: 발송 전 검토 메모.
```
