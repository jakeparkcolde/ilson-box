# 위키 전후 비교

> 부교재 v2.9 · 확인일 2026-11-05



‘내 업무 소개·자주 받는 질문·작업 기준’은 **수강생이 자기 업무로 만드는 빈 양식 이름**으로 유지할 수 있다. Jake의 실제 세 파일인 것처럼 채우지 말고, 왼쪽 참고 예시는 아래 실제 파일로 교체한다.

| 실제 문서 | 원문 또는 실제 기록에 있는 내용 | 내 업무에 옮길 항목 |
|---|---|---|
| 반짝 반려팁 PLAN.md | ‘반짝 반려팁 1편 「물을 잘 안 마실 때」 — 6장 구성안과 캡션 초안’ | 하는 일·결과물·입력 자료 |
| 반짝 반려팁 STANDARD.md | ‘- Never mention a 반짝 product.’ | 지킬 표현 기준 |
| 반짝 1편 예약 인계 문서 | ‘- 발행은 결재함 도장 이후에만(규칙 §5).’ | 사람 확인 뒤 넘길 일 |

**실제 요청 원문을 참고로 보기**

```text
Awo 이런형태로 반짝 고양이 반려팁 만드는거 가능할까? (가림)
```

참고 게시물 주소를 가린 Jake의 직접 입력이다. 이 문장을 ‘위키 먼저 읽기’ 통제 실험의 질문으로 사용한 기록은 없다.

**이 기록으로 새로 쓴 실습 요청문 — 미실행**

```text
반짝 반려팁 1편의 PLAN.md, STANDARD.md, 예약 인계 문서의 가림 사본을 먼저 읽어 주세요.
읽은 문서 이름과 핵심 한 줄을 말하고, 각 문서에서 맡은 역할을 정리해 주세요.
그림·문안 기준, 사람이 고를 부분, 공개 전 확인할 부분을 출처와 함께 적어 주세요.
자료에 없는 것은 확인 필요로 남겨 주세요.
```

**실제 수정 후 남은 기준**: 1편에서 인물 머리 모양이 달라 다시 그린 뒤, STANDARD에는 스타일 참조와 인물 참조를 함께 쓰고 그림을 모두 열어 보라는 규칙이 남았다. 이는 실제 제작·기준 축적 사례다. ‘위키를 읽어서 성능이 좋아졌다’는 통제 비교의 증거는 아니다.


서로 다른 새 대화 두 개에 같은 질문을 씁니다. 가능한 경우 같은 도구·모델을 사용합니다. 내 위키 3장으로 실험할 때는 요청문의 ‘반짝 1편’을 내 업무 이름으로, 세 문서 이름을 ‘내 업무 소개.md’·‘자주 받는 질문.md’·‘작업 기준.md’로 바꿔 질문하세요.

### 복사할 요청문 · 먼저 위키 없이

실제 요청 원문은 위의 실제 문서 3개 절에서 봅니다. 그 요청으로 동일 조건의 답변 전후를 비교한 기록은 **근거 없음**이며, 아래 공통 질문은 이번 실습용 새 초안입니다.

아래 공통 질문을 두 새 대화에서 똑같이 사용합니다. 본인 업무로 바꿀 때도 두 대화의 질문은 같게 둡니다.

**실제 기록 기반 새 요청문 · 미실행** — 당시 Jake 발언·AI의 원문 요청이 아닙니다.

실습할 때는 첫 줄의 사례 이름(예: 반짝 물 1편·깃밥쿠커)을 [내 가게/업무 자료]로 바꾸고 내 자료를 아래에 함께 붙여 넣으세요.

```text
실제 기록의 개인정보 가림 사본을 사용합니다.
반짝 1편의 다음 작업을 시작하기 전 확인할 세 가지와 자료에 없으면 물을 질문 하나를 써 주세요. 실제 답변 비교 실험에서는 이 질문을 두 새 대화에 똑같이 사용하세요.
```


### 비교 기록 · 실제 근거와 미실행

두 개의 지어낸 답을 다른 결과로 꾸며 바꾸지 않는다.

| 비교할 것 | 실제 근거가 있는 기록 | 내 관찰 |
|---|---|---|
| 위키 없이 받은 답 | 같은 질문·조건으로 얻은 실제 답변 근거 없음. 비교 실험 미실행. | 실습 때 받은 실제 답을 여기에 붙인다. |
| 위키를 읽고 받은 답 | 같은 질문·조건으로 얻은 실제 답변 근거 없음. 비교 실험 미실행. | 읽은 자료와 실제 답을 함께 남긴다. |
| 참고할 실제 변화 | 반짝 1편 인물 불일치→인물 참조 추가→STANDARD에 두 참조 사용 기준 저장 | 답변 전후 실험과 다른 제작 기록임을 적는다. |
| 오늘 고칠 기준 | 실제 자료에서 확인한 기준 하나를 고르고, 내 업무 문서에 바꿔 적는다. | 실제 고친 한 줄을 적는다. |

학습 목적은 실제 두 답변을 관찰하고 근거를 확인하는 것이다. 오늘 학생이 두 답변을 만들기 전에는 전후 결과를 채우지 않는다. 실제 답이 같아도 그대로 기록한다.


세 문서를 저장하고 닫았다 다시 엽니다.
