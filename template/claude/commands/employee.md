# 직원 등록과 확인

사용자 요청: $ARGUMENTS

1. 현재 세션이 사용하는 실제 Box 경로를 확인한다. 이름과 역할·업무 범위 중 빠진 항목은 사용자에게 질문한다. 요청 없는 값을 만들지 않는다.
2. `ILSON_HOME="<실제 Box 경로>" ilson people list`로 기존 직원과 부서 ID를 확인한다. 동명이인은 허용한다. 기존 직원을 바꾸려는 것인지 모호하면 질문하고, 기존 직원 편집은 관리자에서 정확한 ID로 처리한다.
3. 새 등록 요청마다 `python3 -c 'import uuid; print(uuid.uuid4().hex)'`로 요청 ID를 한 번 만든다. 아래 명령의 경로·이름·역할은 실제 확인한 값으로 대체하고 셸에서 안전하게 인용한다. 사용자 입력을 셸 코드로 조합하거나 실행하지 않는다.

   `ILSON_HOME="<실제 Box 경로>" ilson people add --name "<확인한 이름>" --role "<확인한 역할>" --request-id "<생성한 요청 ID>"`

   부서를 요청받았으면 list에서 확인한 ID로 `--department-id "<부서 ID>"`를 추가한다. 동일 이름으로 부서를 추정하거나 생성하지 않는다.
4. 종료 코드 0과 JSON `ok: true`, `id`, 저장된 `employee`를 확인한다. `ilson people get <직원 ID>`로 다시 확인할 수 있다. 확인 후 이름·역할·직원 ID를 알려주고 열린 관리자 직원/조직도에 수초 이내 표시됨을 안내한다.
5. 오류·응답 유실은 성공으로 보고하지 않는다. 같은 논리 등록의 재시도는 **같은 요청 ID·같은 입력**을 사용한다. 새 ID로 다시 등록하면 동명이인이 추가될 수 있다. 같은 ID의 입력 변경은 거절되며, 이미 삭제한 직원도 자동 재생성하지 않는다.
6. 서버가 꺼져 있으면 같은 `ILSON_HOME`으로 `ilson open` 후 다시 시도한다. 연결 만료는 같은 요청 ID로 새 CLI 실행을 한다. 다른 Box·권한 오류는 안내하고 멈춘다. 토큰 출력이나 직접 DB 편집은 하지 않는다. 서버 시작·등록은 실제 모델 호출이 필요 없다.

등록은 직원 장부 저장이다. 스킬·도구·외부 발송 권한을 부여하지 않는다. 예약 세션에 필수 정보가 없으면 “확인 필요”로 남기고 등록하지 않는다.
